# 演示脚本（给面试现场用）

> 目标：5 分钟内让面试官相信三件事——**你独立做过一个完整系统**、**你知道它为什么这么设计**、**结果可量化**。
> 演示前 10 分钟照「0. 检查清单」过一遍，现场不要手忙脚乱。

## 0. 演示前检查清单

```bash
cd knowledgeflow-agent
cat .env | grep -E "LLM_API_KEY|LLM_BASE_URL"   # 有 Key 走真实模型；空则自动离线模式
./start_server.sh restart                        # 起服务(首次会自动装依赖/建索引)
curl -s http://127.0.0.1:8000/api/health          # {"status":"ok",...}
curl -s http://127.0.0.1:8000/api/meta | head -c 300
```

- [ ] 浏览器打开 `http://127.0.0.1:8000`，页面能正常渲染（**离线也能走完整链路**）
- [ ] 顶部徽章显示的是你要展示的模式（真实模型 / 离线演示）
- [ ] 提前把「演示问题」点一遍，确认都能答上来（问题来自评测集，不会翻车）
- [ ] 断网预案：`LLM_BACKEND=mock` 也能演示检索链路、引用、Agent 工具、自检
- [ ] 备用材料：`eval/report-*.json`、`pytest -q` 结果、`docs/ARCHITECTURE.md`

## 1. 开场（30 秒）—— 一句话说清是什么

> "这是我空窗期独立做的一个企业知识库智能问答系统 KnowledgeFlow。
> 它解决的问题是：公司文档散落、员工查制度慢、通用大模型会编造公司规定。
> 我做的不只是'接个大模型'——混合检索、意图路由、Agent 工具循环、幻觉自检、可视化检索链路，全部自己实现，并且带可复现的评测。"

## 2. 架构（40 秒）—— 一张图讲完

打开 `docs/ARCHITECTURE.md` 的图（或直接讲）：

> "请求进来先做意图路由：天气、计算、时间这类简单意图 0 次 LLM 直接走工具；
> 知识库问题走向量 + BM25 双路召回，RRF 融合，再生成带编号引用的回答；
> 生成之后还有一道独立的事实核查，证据不支持就拒答；
> 复杂多跳问题走 Agentic 检索，发现证据不够会带着'缺什么'再查一轮。
> 整个过程通过 SSE 把检索阶段、候选片段、耗时实时推给前端。"

## 3. 演示（2 分钟，按顺序点）

**① 关键词问题 → 展示引用与链路**

问：「报销打款是每月几号」
- 点发送，观察回答流式输出；
- 结束时指出：回答里的 `[1]` → 点一下，右侧高亮证据卡片（原文片段 + 相似度）；
- 右侧时间轴：verctor/bm25/fuse 各多少 ms、候选多少；
- 底部 usage：token、LLM 调用次数、成本。

**② 口语化问题 → 展示检索优化的价值**

问：「我出差住酒店的钱怎么找公司要回来」
- 指出：这句话里没有"报销"关键词，BM25 命中不了，向量检索把它找回来了；
- 再切到「对比」视角："我在评测集里专门放了 16 条 paraphrase，纯关键词检索 Top-1 只有 31%，混合检索 + 改写能到 81%。"

**③ 多跳问题 → 展示 Agentic RAG**

问：「出差住宿超标了怎么审批，钱谁出」
- 指出：第一轮只查到了标准，judge 判断"缺审批流程"，第二轮带反馈改写再查；
- 右侧时间轴会出现「第 1 轮 / 第 2 轮检索」以及每轮的 sufficient / missing。

**④ 库外问题 → 展示幻觉自检**

问：「公司股价多少」
- 回答应该是拒答 + 建议，而不是编一个数字；
- 指出：这是**独立 judge + 证据核查**的结果，不是让模型"自查"。

**⑤ Agent 工具（可选，10 秒）**

切模式到 Agent，问：「现在几点，另外算一下 (1200+300)*0.8」
- 右侧出现工具调用卡片（get_datetime / calculator），输入输出耗时一目了然。

## 4. 数据（1 分钟）—— 用数字证明"不是玩具"

```bash
cat eval/report-retrieval.json | head -40     # 六组消融
cat eval/report-e2e.json | python -m json.tool | head -30
python -m pytest -q                            # 103 个离线测试
```

讲三个数字（按最终报告口径）：
1. 检索 Top-1：BM25 62.5% → 混合 85% → 加查询改写 90%（paraphrase 类 31% → 81%）；
2. 意图分类准确率 96.2%（自建 660 条训练集，CPU 推理 <10ms）；
3. 端到端 P50 延迟、平均 token 与单次成本（见 report-e2e.json）。

> "这些数字都能用仓库里的脚本复现：`make eval` 一条命令跑完。"

## 5. 取舍（1 分钟）—— 展示判断力

> "有三件事我**没有**做，因为评测数据不支持：
> HyDE 在中文短查询上没有稳定收益、还多 2 秒，所以默认关闭；
> 重排模型 1.1GB、每查询多 1.5 秒，收益要按语料看，所以做成开关；
> 向量库也没上 Chroma——7 万块以内 numpy 精确检索 <15ms，上 ANN 是过度设计。
> 我的原则是：先量化，再决定；每个'不用'都写在 docs/DECISIONS.md 里。"

## 6. 演砸了怎么办（兜底）

| 情况 | 处理 |
| --- | --- |
| 网络/Key 失效 | 页面会显示"离线演示模式"，检索、引用、Agent、自检仍可演示；说明"线上是真实模型，现在展示的是降级路径" |
| 服务起不来 | `./start_server.sh status` → `tail -50 logs/server.log`；或直接 `python -m app.cli.main --mode fast` 演示 CLI |
| 模型太慢 | 切「快速」模式（0.5s 级），或问确定性意图（现在几点）展示 0 LLM 快路径 |
| 被问倒了 | 承认边界 + 给出验证方法："这个我还没测，不过评测脚本可以加一组实验来验证" |
